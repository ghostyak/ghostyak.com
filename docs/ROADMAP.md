# ghostyak.com 로드맵

ghostyak.com은 GhostYak의 소프트웨어를 소개하고 배포하는 공식 웹사이트다. 초기에는 첫 번째 제품인 **Boxes**를 방문자가 쉽게 이해하고 다운로드할 수 있도록 하는 데 집중한다.

Stardock.com의 제품 중심 정보 구조를 참고하되 디자인을 그대로 복제하지 않는다. Next.js App Router와 Server Component를 우선 사용하며, 필요한 기능만 점진적으로 추가한다.

## 기본 원칙

- [ ] Boxes의 가치와 다운로드 경로를 가장 먼저 보여준다.
- [ ] Next.js 기본 기능을 우선 사용하고 불필요한 UI 라이브러리는 추가하지 않는다.
- [ ] 모바일과 데스크톱을 모두 지원한다.
- [ ] 제품과 콘텐츠가 늘어나도 확장할 수 있는 구조를 유지한다.
- [ ] 로그인, 결제, 검색, CMS 등은 실제로 필요해질 때 도입한다.

## 1단계: 최소 기능 홈페이지

목표: 방문자가 Boxes가 무엇인지 이해하고 설치 파일을 다운로드할 수 있게 한다.

- [x] Boxes의 한 줄 소개를 작성한다.
- [x] 핵심 기능 3개를 선정하고 짧은 설명을 작성한다.
- [x] 지원 운영체제와 최소 요구사항을 정리한다.
- [x] 현재 버전과 파일 크기를 확인한다.
- [x] 실제 설치 파일의 GitHub Releases 다운로드 URL을 준비한다.
- [x] 임시 제품 아이콘과 대표 이미지를 준비한다.

### 사이트 구조

- [x] 공통 기본 레이아웃을 만든다.
- [x] 사이트 이름과 내비게이션이 있는 헤더를 만든다.
- [x] 저작권과 프로젝트 링크가 있는 푸터를 만든다.
- [x] Boxes 소개와 다운로드 선택 영역으로 연결되는 히어로 영역을 만든다.
- [x] 핵심 기능 3개를 보여주는 영역을 만든다.
- [x] Free와 Pro 평가판을 비교하고 각각 받을 수 있는 다운로드 영역을 만든다.
- [x] 로고와 실제 제품 이미지가 준비되기 전 사용할 임시 자산을 만든다.

### 품질 기준

- [ ] 작은 화면부터 큰 화면까지 반응형으로 표시되는지 확인한다.
- [x] 키보드만으로 내비게이션과 다운로드 버튼을 사용할 수 있게 한다.
- [x] 문서 제목과 설명 등 기본 SEO 메타데이터를 설정한다.
- [x] Open Graph 등 기본 공유 메타데이터를 설정한다.
- [x] sitemap과 robots.txt를 제공한다.
- [x] favicon에 임시 Boxes 아이콘을 적용한다.
- [x] 다운로드 링크가 실제 GitHub 릴리스 자산을 가리키는지 확인한다.

### 1단계 완료 조건

- [x] 첫 화면에서 Boxes의 목적과 다운로드 선택 경로를 바로 찾을 수 있다.
- [x] Free와 Pro 평가판 다운로드 버튼으로 각 설치 파일을 받을 수 있다.
- [ ] 모바일과 데스크톱에서 주요 콘텐츠가 정상적으로 표시된다.
- [x] 배포 가능한 정적 빌드가 생성된다.

## 2단계: Boxes 제품 페이지

목표: 홈페이지는 간결하게 유지하면서 Boxes에 대한 자세한 정보를 제공한다.

- [ ] `/products/boxes` 페이지를 만든다.
- [ ] 홈페이지에서 Boxes 제품 페이지로 연결한다.
- [ ] 기능별 상세 설명을 추가한다.
- [ ] 실제 사용 화면과 스크린샷을 추가한다.
- [ ] 시스템 요구사항을 자세히 작성한다.
- [ ] 다운로드 및 설치 방법을 작성한다.
- [ ] 자주 묻는 질문을 추가한다.
- [ ] 알려진 문제와 지원 경로를 안내한다.

## 3단계: 제품 데이터 구조화

목표: 제품 정보를 한곳에서 관리하고 새로운 제품을 쉽게 추가할 수 있게 한다.

- [x] `src/data/products.ts`에 제품 데이터 모델을 만든다.
- [ ] 이름, 설명, 버전, 출시일, 운영체제, 파일 크기, 에디션별 다운로드 URL을 데이터로 관리한다.
- [x] `Header`, `Footer`, `FeatureCard`, `EditionCard`를 재사용 가능한 컴포넌트로 정리한다.
- [ ] 페이지에 직접 작성된 제품 정보를 공통 데이터로 교체한다.
- [ ] 다운로드 URL 변경 시 한 파일만 수정하면 되도록 확인한다.

## 4단계: 릴리스와 지원 정보

목표: Boxes 사용자가 최신 버전과 문제 해결 정보를 신뢰할 수 있게 제공한다.

- [ ] 변경 내역 페이지를 만든다.
- [ ] 버전별 릴리스 노트를 작성한다.
- [ ] 설치 및 사용 가이드를 작성한다.
- [ ] 버그 제보와 문의 방법을 안내한다.
- [ ] 코드 서명 및 파일 무결성 정보를 검토한다.
- [ ] GitHub Releases 등 외부 배포 저장소 사용 여부를 결정한다.
- [ ] 문서가 늘어나면 MDX 또는 별도 콘텐츠 관리 방식 도입을 검토한다.

## 5단계: 제품군 확장

목표: Boxes 외의 제품이 생겼을 때 동일한 구조로 소개하고 배포한다.

- [ ] `/products` 제품 목록 페이지를 만든다.
- [ ] 제품 데이터만 추가해 제품 카드와 상세 페이지를 만들 수 있게 한다.
- [ ] 홈페이지에 여러 제품을 소개할 수 있는 제품 영역을 추가한다.
- [ ] 필요하면 공지사항 또는 블로그를 추가한다.
- [ ] 필요하면 지원 문서와 회사 소개 페이지를 추가한다.

## 현재 범위에서 제외

다음 기능은 필요성이 확인되기 전까지 만들지 않는다.

- 사용자 계정과 로그인
- 장바구니와 결제
- 뉴스레터
- 커뮤니티와 포럼
- 사이트 검색
- CMS
- 복잡한 애니메이션
- 다운로드 통계 시스템

## 권장 프로젝트 구조

```text
src/
├── app/
│   ├── globals.css
│   ├── layout.tsx
│   └── page.tsx
├── components/
│   ├── FeatureCard.tsx
│   ├── EditionCard.tsx
│   ├── Footer.tsx
│   └── Header.tsx
├── data/
│   └── products.ts
```

이 구조는 목표 형태이며 1단계에서 필요하지 않은 파일은 미리 만들지 않는다.
