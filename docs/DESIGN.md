# 디자인 시스템

## 목적과 적용 범위

ghostyak.com의 신규 UI와 기존 UI 개편에는 **Tailwind CSS와 DaisyUI를 기본 디자인 시스템으로 사용한다.** DaisyUI는 버튼, 카드, 메뉴, 배지, 알림 등 공통 UI의 기준을 제공하고 Tailwind CSS는 레이아웃, 간격, 반응형 동작과 예외적인 세부 조정을 담당한다.

전체 공개 화면은 Tailwind CSS와 DaisyUI로 구성한다. `src/app/globals.css`에는 Tailwind CSS·DaisyUI 로딩, GhostYak 테마 토큰과 최소한의 전역 기본 규칙만 둔다.

## 우선순위

UI를 구현할 때 다음 순서로 선택한다.

1. 의미에 맞는 DaisyUI 컴포넌트와 상태 클래스를 사용한다.
2. 배치, 간격, 크기와 반응형 처리는 Tailwind CSS 유틸리티로 구성한다.
3. 반복되는 시각 속성은 DaisyUI 테마의 의미 기반 토큰으로 정의한다.
4. DaisyUI와 Tailwind CSS로 표현하기 어려운 경우에만 컴포넌트 전용 CSS를 추가한다.
5. 전역 CSS에는 리셋, 기본 타이포그래피, 브랜드 자산 및 불가피한 공통 규칙만 둔다.

새 컴포넌트에 기존의 독자적인 버튼·카드·배지 클래스를 추가하지 않는다. DaisyUI 컴포넌트와 같은 역할을 하는 사용자 정의 CSS를 만들어야 한다면 코드 주석 또는 관련 문서에 이유를 기록한다.

## 시각 원칙

- 제품과 다운로드 경로가 장식보다 먼저 보이게 한다.
- 밝고 차분한 기본 화면과 명확한 한 가지 주 행동을 유지한다.
- 한 화면에서 강조 색상을 경쟁적으로 사용하지 않는다.
- 카드, 그림자, 둥근 모서리는 정보 계층을 구분하는 데 필요한 만큼만 사용한다.
- 모바일 화면을 먼저 설계하고 콘텐츠 폭이 커질 때 단계적으로 확장한다.
- 애니메이션은 상태 변화의 이해를 돕는 경우에만 사용하며 과도한 움직임을 피한다.

## 색상과 테마

DaisyUI의 의미 기반 색상 이름을 우선 사용한다.

- `primary`: 가장 중요한 다운로드 또는 구매 행동
- `secondary`: 같은 수준의 두 번째 선택지
- `accent`: 제한적인 강조 요소
- `neutral`: 헤더와 푸터의 짙은 브랜드 배경. `neutral-content`와 함께 사용해 본문 및 주요 행동의 `primary` 색상과 경쟁하지 않게 한다.
- `base-100`, `base-200`, `base-300`: 화면과 카드의 배경 계층
- `info`, `success`, `warning`, `error`: 의미가 분명한 상태 안내

컴포넌트 코드에 임의의 색상값을 반복해서 작성하지 않는다. 브랜드 색상은 DaisyUI 사용자 테마에 정의하고 의미 기반 클래스에서 사용한다. 제품 이미지, 소셜 브랜드 색상, 특별한 그래픽 표현은 예외로 둘 수 있다.

라이트 테마를 기본으로 제공한다. 다크 테마를 추가할 때는 개별 컴포넌트에 다크 색상을 직접 지정하지 않고 DaisyUI 테마 토큰으로 전환한다.

## 컴포넌트 규칙

가능한 경우 다음 DaisyUI 구성을 기본으로 삼는다.

| 용도 | 기본 구성 |
| --- | --- |
| 헤더 | `navbar` |
| 언어와 보조 메뉴 | `dropdown`, `menu` |
| 주요 행동 | `btn btn-primary` |
| 보조 행동 | `btn btn-secondary` 또는 `btn-outline` |
| 에디션과 기능 정보 | `card` |
| 짧은 상태 표시 | `badge` |
| 경로 표시 | `breadcrumbs` |
| 안내와 오류 | `alert` |
| 로딩과 진행 상태 | `loading`, `progress` 또는 명시적인 카운트다운 |
| 푸터 | `footer` |

링크 이동에는 링크를, 현재 화면의 상태 변경에는 버튼을 사용한다. 시각적으로 버튼처럼 보인다는 이유로 의미가 맞지 않는 HTML 요소를 선택하지 않는다.

같은 패턴이 두 곳 이상에서 사용되거나 동작·접근성 규칙을 포함하면 `src/components/`의 재사용 컴포넌트로 분리한다. 단순한 DaisyUI 마크업을 지나치게 얇은 래퍼 컴포넌트로 만들지는 않는다.

## 타이포그래피와 간격

- 제목 계층은 페이지마다 `h1` 하나를 기준으로 논리적인 순서를 유지한다.
- 본문은 긴 줄을 피하고 읽기 쉬운 최대 폭을 둔다.
- 글자 크기와 간격은 Tailwind CSS의 기본 스케일을 우선 사용한다.
- 임의 값은 이미지 비율이나 실제 측정값처럼 명확한 이유가 있을 때만 사용한다.
- 같은 종류의 섹션은 동일한 수직 간격과 콘텐츠 폭을 공유한다.

## 반응형과 다국어

- 320px 너비에서도 가로 스크롤 없이 주요 행동을 사용할 수 있어야 한다.
- 터치 대상은 최소 44×44px 수준을 유지한다.
- 작은 화면에서는 두 개 이상의 주요 행동을 세로로 배치할 수 있다.
- 번역문이 길어져도 버튼과 메뉴의 텍스트가 잘리거나 겹치지 않아야 한다.
- 언어 선택 메뉴는 키보드와 터치로 열고 스크롤할 수 있어야 한다.
- 언어별로 레이아웃을 따로 만들지 않고 동일한 컴포넌트 구조를 공유한다.

## 접근성

- 모든 상호작용은 키보드로 사용할 수 있어야 한다.
- DaisyUI가 제공하는 시각 스타일과 별개로 적절한 HTML 의미와 ARIA 이름을 제공한다.
- 포커스 표시를 제거하지 않는다.
- 아이콘만 있는 버튼과 링크에는 접근 가능한 이름을 제공한다.
- 색상만으로 상태나 선택을 구분하지 않는다.
- 오류는 문제와 해결 방법을 함께 설명한다.
- 움직임이 있는 UI는 `prefers-reduced-motion`을 존중한다.

## Server Component 원칙

DaisyUI는 시각 스타일을 위한 시스템이며 Client Component 사용 이유가 아니다. 페이지와 컴포넌트는 계속 Server Component를 기본으로 유지한다. 상태, 이벤트 처리, 타이머 또는 브라우저 API가 필요한 가장 작은 경계에만 `"use client"`를 사용한다.

## 유지와 확장 규칙

- 모든 공개 화면은 DaisyUI 컴포넌트와 Tailwind CSS 유틸리티를 일관되게 사용한다.
- 기존의 독자적인 버튼, 카드, 메뉴, 배지와 레이아웃 컴포넌트 클래스를 다시 도입하지 않는다.
- 반복되는 스타일은 임의 CSS 대신 DaisyUI 테마 토큰 또는 재사용 컴포넌트로 올린다.
- 더 이상 사용하지 않는 유틸리티와 컴포넌트 코드는 참조 여부를 확인한 뒤 함께 제거한다.
- DaisyUI 또는 Tailwind CSS를 업그레이드할 때 테마, 빌드와 모든 공개 경로를 함께 검증한다.

## UI 변경 검토 목록

- DaisyUI의 기존 컴포넌트로 해결할 수 있는지 확인했다.
- 색상은 의미 기반 테마 토큰을 사용한다.
- 모바일, 데스크톱과 긴 번역문에서 레이아웃을 확인했다.
- 키보드, 포커스 표시와 명암 대비를 확인했다.
- 불필요한 Client Component와 사용자 정의 CSS를 추가하지 않았다.
- 디자인 규칙이나 공개 동작이 바뀌었다면 관련 문서를 갱신했다.
- `npm run lint`와 `npm run build`를 통과했다.
